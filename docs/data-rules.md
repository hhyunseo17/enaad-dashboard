# 매출 분류 대원칙 (data-rules)

> 이 문서는 `reviewer` 에이전트의 검증 기준이자, 데이터 로직 수정 시의 근거다.
> 모든 규칙은 실제 운영 데이터에서 검증된 값이며, 임의로 바꾸지 말 것.

## 1. 본부매출 기준
- 컬럼 `본부매출여부`가 `본부매출`인 행만 매출로 집계.
- 모든 집계 함수는 예외 없이 이 필터를 통과해야 한다.

## 2. 매출기준 (취급고 / 회계)
- 컬럼 `매출기준`: `실적` 또는 `회계조정`.
- **취급고 모드**: `실적`만 합산.
- **회계 모드**: `실적` + `회계조정` 합산.
- 프론트 전역변수 `revenueBasisMode`('performance' | 'accounting')로 분기.

## 3. 대분류 재분류 (5종 고정)
최종 대분류는 아래 5종만 존재한다. (재분류 로직은 `data-loader.js`)
- 일반광고
- IMC
- 인포머셜
- 큐톤광고 — 중분류 `skylife큐톤` 포함
- 기타광고 — 어드레서블 / 콘텐츠편성 / 기타광고 / 대행수익 등을 통합

주의: **어드레서블은 별도 대분류가 아니다.** 기타광고로 통합.

검증 기준 (참고 분포, 2025 기준):
- 일반광고 ~20,142 / 기타광고 ~2,985 / 인포머셜 ~1,651 / IMC ~1,020 / 큐톤광고 ~259

## 4. 매출 미인식 항목
- **대행수익**: 원칙적으로 매출 미인식. 단 중분류 `skylife큐톤`(약 39건)만 큐톤광고로 인정.
- **교환광고**(약 586건): 전부 매출 미인식.

## 5. commonMatch (단일 필터 함수)
`js/core/filters.js`에 단 하나만 존재. 다음을 모두 검사:
- 본부매출 여부
- 매출기준(취급고/회계) 모드
- 부서/채널/방송·디지털 선택 필터
- 대행사/광고주 검색어
- (기능별) 대분류 한정, 배분수익 제외, 1/N 제외 등

**새 compute 함수는 이 함수를 재사용한다.** 필터 로직을 복붙해서 우회하지 말 것 — 과거 이 중복(8곳)이 규칙 변경 시마다 버그를 유발했다.

## 6. K2그룹 등 중복 계약 병합 (업프론트)
- 광고주(업프론트용) + 계약기간 기준으로 계약을 묶는다. 대행사가 여러 개여도 1개 계약.
- **같은 광고주 + 같은 계약금액 텍스트가 겹치는 기간으로 여러 번 등재된 경우 병합**한다(계약 갱신/재기재로 인한 중복). 예: K2그룹 2025년 "8억원(K2그룹 통합)"이 1~12월/3~12월로 두 번 → 하나로.
- 동원그룹+동원F&B는 원본에 이미 `동원그룹+동원F&B` 단일 광고주로 통합되어 있음(2.5억).
- 이 병합은 **data-loader에서만** 수행. UI에서 재구현 금지.

## 7. 업프론트 계약금액 (근사치)
- 계약금액 텍스트 파싱: 맨 앞 "N억원"을 GROSS, "(Net M억원)"이 있으면 M을 NET 기준액으로.
- 계약 내 행 중 하나라도 GROSS/NET이 `NET`이면 그 계약은 NET 기준액 사용.
- **월할 계산**: 계약기간을 월 단위 전개, 선택된 연/월과 겹치는 개월수 ÷ 전체 개월수를 곱함.
- **연걸침 계약은 정확 재현 불가**(팀 수기 배분). KPI에는 "약 XX.XX억원(월할 추정치)"로 표기.

## 8. 대행사/대행사그룹 정규화 (data-loader)
- `에스엠컨텐츠앤커뮤니케이션즈` → `SM C&C` (대행사·대행사그룹 모두)
- 옴니콤광고그룹: TBWA KOREA / 비비디오코리아 / 옴니콤미디어그룹코리아 / PHD → 통합
- 덴츠(G) / 레오버넷(G) / 명애드컴 / HSAD(G) 매핑 규칙 존재

## 9. 금액 표기 규칙
- 피벗 테이블: **백만원 단위, 소수 1자리**. 기본 접힘.
- 차트/KPI: **억원 단위**.
- 부서 정렬: 매출순이 아니라 커스텀 순서(광고사업1팀 → 2팀 → 3팀 → …). `customDeptOrder`.
